# Contributing

## Синхронизация зеркал

Репозиторий доступен на GitHub и SourceCraft; разрабатывать можно на любой из платформ - ветки и PR заводятся там, где ведется работа. Состояния main и тегов выравниваются автоматически скриптом `tools/sync_mirrors.py`: он запрашивает состояние обоих зеркал и доставляет отстающему fast-forward push, без force и удаления рефов.

Обертки CI запускают скрипт при пуше в main и при пуше тегов: `trunk.yml` в GitHub Actions и `trunk-workflow` в `.sourcecraft/ci.yaml`. Платформа, в CI которой выполняется прогон, определяется скриптом по штатным переменным окружения (`GITHUB_ACTIONS`, `SOURCECRAFT_CI`) - свое состояние берется из origin рабочей копии, чужое - по сети.

При расхождении main или конфликте тегов (разное состояние одного тега на зеркалах) скрипт печатает диагностику и завершается с кодом 1, ничего не меняя; расхождение разрешается локально - merge одной стороны в другую, затем повторный прогон. Повторный запуск безопасен: при синхронных зеркалах скрипт не выполняет действий, поэтому синхронизация не зацикливается. Сбой синхронизации не прерывает работу конвейера - в лог пишется предупреждение.

## Ключи и секреты синхронизации

Каждому направлению пуша соответствует своя пара ed25519. Приватные половины хранятся только в секретах платформ и в репозиторий не попадают.

- Пуш SourceCraft CI в GitHub: публичная половина - deploy key репозитория GitHub с правом записи; приватная - секрет SourceCraft `SYNC_GITHUB_SSH_KEY` (репозиторий -> Settings -> Secrets and variables).
- Пуш GitHub Actions в SourceCraft: публичная половина - SSH-ключ профиля SourceCraft (Домой -> Доступ -> SSH-ключи; репозиториевых deploy-ключей платформа не предусматривает, ключ профиля действует в рамках прав аккаунта); приватная - секрет GitHub Actions `SYNC_SOURCECRAFT_SSH_KEY`.

Ключи генерируются отдельно под каждый репозиторий. При компрометации пара перегенерируется, новые половины закладываются в секреты и на соответствующую платформу - прочих изменений не требуется.
